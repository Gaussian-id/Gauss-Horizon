<Callout type="info">Chiron Horizon CLI is a dedicated command line package for terminal, script, and coding-agent workflows. It shares Chiron Horizon connection storage and SQL safety rules with the MCP server.</Callout>

## Availability in 0.1.2

Chiron Horizon 0.1.2 does not publish standalone CLI or npm packages. Use the desktop application for local database workflows and enable its built-in MCP service from **Settings → MCP** when an MCP-capable client needs access.

Developers can build the CLI from this repository with the same pinned Rust toolchain used by the desktop release:

```bash
cargo run -p chiron-horizon-cli -- --help
```

Set `CHIRON_HORIZON_DATA_DIR` when working with a custom or portable Chiron Horizon data directory.

## Common Commands

```bash
chiron-horizon doctor
chiron-horizon capabilities
chiron-horizon connections list --json
chiron-horizon connections list --format csv
chiron-horizon schema list local --json
chiron-horizon schema describe local users --json
chiron-horizon query local "select count(*) as total from users" --json
chiron-horizon query local "select id, name from users" --format csv
chiron-horizon query local "select * from users" --limit 50 --timeout 10s --json
chiron-horizon query local --file ./query.sql --json
chiron-horizon context local --tables users,orders
chiron-horizon open local users
```

## Diagnostics

Use `chiron-horizon doctor` to inspect local Chiron Horizon paths, connection-store health, and whether the desktop bridge is available:

```bash
chiron-horizon doctor
chiron-horizon doctor --json
```

The standalone npm CLI is deferred for 0.1.2. Rebuild the CLI from this repository when a source-development binary is needed.

Use `chiron-horizon capabilities` to see which database types can be queried directly and which currently require Chiron Horizon Desktop:

```bash
chiron-horizon capabilities
chiron-horizon capabilities --json
```

The CLI binary currently lists PostgreSQL, Redshift, MySQL, Doris, StarRocks, Manticore Search, SQLite, rqlite, KWDB, and QuestDB as direct-query types. `chiron-horizon capabilities` is authoritative for the installed version. Other types require a running Chiron Horizon Desktop bridge or their Agent/external-driver infrastructure.

## Execution Modes

### Local Storage

By default, CLI reads the same `chiron-horizon.db` connection store used by Desktop and MCP. `CHIRON_HORIZON_DATA_DIR` must point to the directory containing `chiron-horizon.db`.

- Direct-query types can run while Desktop is closed
- Bridge types require Desktop to be running and discoverable through the bridge port file in the data directory
- Agent/JDBC, DuckDB, and other external-driver paths still require matching components installed through Chiron Horizon
- `chiron-horizon open` is always a Desktop UI operation and returns `CHIRON_HORIZON_NOT_RUNNING` when the app is unavailable

### Chiron Horizon Web and Docker

Set `CHIRON_HORIZON_WEB_URL` to use a deployed Chiron Horizon Web backend instead of local connection storage:

```bash
CHIRON_HORIZON_WEB_URL=https://chiron-horizon.example.com \
CHIRON_HORIZON_WEB_PASSWORD='your-login-password' \
chiron-horizon connections list --json
```

`CHIRON_HORIZON_WEB_PASSWORD` is the Web login password. In Web mode, connections, permissions, drivers, and file paths belong to the server environment. `chiron-horizon open` still targets a local Desktop bridge and should not be treated as a remote Web automation API.

## Default Connection

Set `CHIRON_HORIZON_CONNECTION` to omit the connection name for query and context commands:

```bash
CHIRON_HORIZON_CONNECTION=local chiron-horizon query "select 1" --json
CHIRON_HORIZON_CONNECTION=local chiron-horizon context --tables users,orders
```

## Output Formats

Use `--json` or `--format json` for stable machine-readable output. Use `--format csv` for query, connection, and schema data that should be piped into other command line tools.

```bash
chiron-horizon query local "select id, name from users" --format csv
```

Errors are written to stderr and return a non-zero exit code.

## Query Controls

`chiron-horizon query` executes SQL for SQL connections and accepts supported Mongo shell commands for MongoDB connections. Redis is not executed through this command; use the MCP Redis tool or the Chiron Horizon workspace instead. Query mode is read-only by default.

```bash
chiron-horizon query local "select * from users" --limit 50 --timeout 10s --json
```

Durations accept `ms`, `s`, or `m`, such as `500ms`, `10s`, or `1m`.

Use `--allow-writes` for non-dangerous write statements:

```bash
chiron-horizon query local "update users set name = 'Ada' where id = 1" --allow-writes
```

Dangerous SQL such as `DROP`, `TRUNCATE`, and `ALTER` requires both `--allow-writes` and `--allow-dangerous-sql`. Explicit transaction statements remain blocked by CLI; use [MCP stateful sessions](/en/docs/mcp#stateful-query-sessions) or the Chiron Horizon editor for pinned multi-step sessions.

Writes and DDL against production databases remain blocked even when both flags are present. Production detection, SQL risk classification, connection read-only protection, and database privileges form independent upper bounds; the flags are not a production bypass.

## SQL Starting With a Dash

Pass `--` before SQL that starts with a dash:

```bash
chiron-horizon query local --json -- "-- comment
select 1"
```

## Error Codes

CLI JSON errors use stable codes:

| Code                     | Meaning                                             |
| ------------------------ | --------------------------------------------------- |
| `UNKNOWN_OPTION`         | An unsupported flag was provided                    |
| `INVALID_OPTION`         | A flag is missing a value or has an invalid value   |
| `INVALID_ARGUMENT`       | Positional arguments are missing or conflicting     |
| `CONNECTION_STORE_ERROR` | Chiron Horizon connection storage exists but could not be read |
| `CONNECTION_NOT_FOUND`   | No Chiron Horizon connection matched the requested name        |
| `SQL_BLOCKED`            | SQL safety rules blocked execution                  |
| `CHIRON_HORIZON_NOT_RUNNING`        | Chiron Horizon Desktop bridge is unavailable                   |
| `ERROR`                  | Unexpected runtime failure                          |

## Desktop Deep Links

Chiron Horizon Desktop supports deep links for launching the client from browsers, bastion hosts, or scripts.

Launch or focus Chiron Horizon without opening another dialog:

```bash
open 'chiron-horizon://open'
```

A web button can link to the protocol directly:

```html
<a href="chiron-horizon://open">Open in Chiron Horizon</a>
```

Use `chiron-horizon://connection/new` to open the new connection dialog with connection fields prefilled.

DSN mode:

```bash
open 'chiron-horizon://connection/new?url=postgres%3A%2F%2Fapp%3Asecret%40db.internal%3A5432%2Forders'
```

Field mode:

```bash
open 'chiron-horizon://connection/new?type=mysql&host=127.0.0.1&port=3306&user=root&password=secret&database=test'
```

Supported fields:

| Field        | Meaning                                                                                  |
| ------------ | ---------------------------------------------------------------------------------------- |
| `type`       | Database type; service types include `etcd`, `consul`, `nacos-v2`, `nacos-v3`, `r-nacos` |
| `url`        | Database DSN; URL encoding is recommended                                                |
| `name`       | Display name in Chiron Horizon; when omitted, Chiron Horizon uses `database`, then `host`                      |
| `host`       | Hostname or IP address                                                                   |
| `port`       | Port                                                                                     |
| `user`       | Username                                                                                 |
| `password`   | Password                                                                                 |
| `database`   | Database name; for Redis this can be a DB index such as `0`                              |
| `url_params` | Extra connection parameters, such as `sslmode=require`                                   |
| `ssl`        | Enable SSL when set to `true`                                                            |
| `one_time`   | Automatically connect when set to `true`, then delete the connection after disconnecting |

One-time connection example:

```bash
open 'chiron-horizon://connection/new?type=redis&host=127.0.0.1&port=6379&user=default&password=secret&database=0&one_time=true'
```

Nacos and service-registry examples:

```bash
open 'chiron-horizon://connection/new?type=consul&host=127.0.0.1&port=8500&password=acl-token'
open 'chiron-horizon://connection/new?type=nacos-v3&host=127.0.0.1&port=8848&user=nacos&password=secret'
open 'chiron-horizon://connection/new?type=r-nacos&url=http%3A%2F%2F127.0.0.1%3A8848%2Fnacos&user=admin&password=secret'
```

`nacos` is an alias for `nacos-v2`, and `rnacos` is an alias for `r-nacos`. In URL mode, service endpoint paths are preserved; top-level `host`, `port`, `user`, `password`, and `ssl` fields override values from `url`. For Consul, `password` is the ACL token. Nacos requires `user` when `password` is present. Omitting `v` or using `v=1` selects the current deep-link protocol; other versions are rejected.

<Callout type="info">Before testing system-level `chiron-horizon://` launches, install and open Chiron Horizon Desktop once so the operating system can register the URL scheme. On macOS, use `open 'chiron-horizon://open'` or `open 'chiron-horizon://connection/new?...'` to test it.</Callout>

<Callout type="warning">A deep link may expose a database password or Consul ACL token in browser and terminal history. Do not put credential-bearing links in shared logs, shell history, tickets, or chat messages.</Callout>

## Codex

Codex can call the CLI directly from shell tools:

```bash
chiron-horizon schema describe local users --json
chiron-horizon context local --tables users,orders | codex exec "Write a retention query"
```
