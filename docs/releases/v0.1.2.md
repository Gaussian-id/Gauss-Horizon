# Chiron Horizon 0.1.2

Context-aware schema inspection, explicit access contracts for every registered database type, and initial ChironDB relational interoperability.

## Context-Aware Schema Viewer

- Added a default-enabled Schema Viewer action to the main toolbar and a compatible Settings toggle.
- Added a connected-connection and hierarchical scope picker with search and pagination.
- Added relational ERDs, graph metagraphs, expandable declared-JSON trees, vector/time-series/wide-column/key-value/service summaries, and ChironDB composite facets.
- Preserved the legacy sidebar Diagram action by routing it into the new viewer with the selected object preselected.
- Added matching desktop and web transports for descriptor, scope, and schema-view responses.
- Added explicit `complete`, `partial`, `absent`, and `notExposed` metadata states. Permission and transport failures remain errors.

## Database access coverage

- Added manifest-driven picker, runtime-provider, connect, test-connection, and Schema Viewer contracts for all 82 registered connection types and 106 product/version profiles.
- Preserved merged selectors for products such as Ignite, InfluxDB, and MQ while retaining the correct database type and driver profile.
- Kept safety guards, read-only restrictions, production protection, and genuinely unsupported operations in place.
- Added fail-closed JDBC and plugin capability handshakes so legacy providers are not advertised as viewer-capable without declaring support.

## Native metadata and privacy

- Relational stores expose available tables/views, columns, primary keys, indexes, and foreign keys; ERDs still render when relationship metadata is unavailable.
- MongoDB uses validators and collection options; Elasticsearch-family stores use mappings/settings; Meilisearch uses declared settings; DynamoDB uses native key and index definitions.
- Graph, vector, time-series, wide-column, key-value, and service adapters return only native metadata appropriate to their protocols.
- Schema discovery does not sample MongoDB documents, Weaviate objects, Redis values, ZooKeeper/Consul values, MQ messages, MQTT payloads, or other user data.

## ChironDB relational interoperability

- Added the `ChironDB Relational (PostgreSQL wire)` profile on port `7403`.
- Internally verified Horizon connect/test, sequential DDL and DML, joins, table discovery, and column discovery against a locally built ChironDB server.
- ChironDB's current PostgreSQL-wire preview does not expose index and foreign-key catalogs compatibly; Horizon reports those facets as partial instead of fabricating metadata.

## Fixes and release operation

- Improved scoped MongoDB metadata behavior while keeping authorization failures visible and actionable.
- Corrected the Settings appearance preview to use the Gauss logo.
- The application checks GitHub-backed release metadata and changelog data periodically, with bundled fallback data for offline use.
- GitHub Release publication consumes this versioned release-note file after the tag, main-branch, version, build, and checksum gates pass.
